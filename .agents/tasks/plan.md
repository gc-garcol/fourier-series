## Design decisions

- Registry: an array `SAMPLES` of `{ id, label, draw }` (array, not object, so the dropdown order is stable and explicit). Heart is first and `DEFAULT_SAMPLE_ID = 'heart'`. An array keeps ES5 simple and gives the UI one source of truth.
- Registry contract is `draw(g, size)`, where `size` is the canvas pixel size. `loadSample` always uses `size = 400`, so the new draw functions are written directly in 400x400 coordinates and the heart keeps its existing math using `size`. No scaling transform is added.
- Overlapping parts are drawn as separate fills in the same black. The union is what the tracer sees. This is simpler than one compound path. The crescent is the exception: fill black outer circle, then fill a white inner circle on top (the offscreen canvas is opaque white, so the white fill is exact).
- UI: a `<select id="sample-select">` with a real `<label>` plus the existing `#sample-btn`, in a `.row`. The select loads on `change` so picking a shape works in one step. The button is kept (relabelled "Load") and reloads the currently selected sample. This matters because after an upload or a load error the select's value has not changed, so `change` would not fire for re-picking the same sample. A native select is keyboard accessible, labelled, and works on narrow screens. Options are populated from `SAMPLES` in JS so the list cannot drift from the registry.
